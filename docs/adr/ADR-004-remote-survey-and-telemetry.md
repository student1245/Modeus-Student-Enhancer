# ADR-004: Удаленное управление опросами и бессерверная телеметрия (Remote Survey Engine)

## Status

Accepted | Implemented (v2.2.2)

## Context

- **Initiator / Decision Owner:** `student1245`
- **Stakeholders:** Пользователи расширения (студенты ТюмГУ), разработчики расширения Modeus Student Enhancer.
- **Current state:** Подсистема интерактивных опросов и анонимной телеметрии полностью реализована в кодовой базе (`src/content.js`, `src/injected.js`, `data/survey.json`, `styles/styles.css`).
- **Why now:** Фиксация архитектурных развилок и контрактов по сбору обратной связи и приоритизации продуктовых функций. Необходимо защитить проект от неоправданного усложнения инфраструктуры (поднятие собственного бэкенда), исключить утечки персональных данных и не допустить появления устаревших анкет («зомби-опросов») в оффлайн-сборках.
- **Constraints:**
  1. *Zero Dedicated Backend:* Полное отсутствие собственного платного сервера, базы данных или выделенного API-шлюза для расширения.
  2. *Zero Tracking / Strict Privacy:* Категорический запрет на сбор персональных данных студентов (ФИО, email, student ID, академические группы, оценки). Полная анонимность ответов.
  3. *Zero Offline Zombies:* В релизном бандле расширения не должно быть зашитых оффлайн-опросов, которые показывались бы пользователям устаревших версий спустя месяцы после закрытия анкеты.
  4. *Decoupled Lifecycle (Bypass Web Store Review):* Запуск, редактирование вопросов и остановка опросов должны производиться дистанционно в реальном времени без ожидания модерации обновлений в Chrome Web Store или публикации новых релизов.
  5. *CORS & Redirect Handling:* Google Apps Script Web App отвечает HTTP 302 переадресацией и не возвращает CORS-заголовки (`Access-Control-Allow-Origin: *`) для браузерных запросов с произвольных доменов при произвольных типах содержимого.
- **Assumptions:**
  1. Домен `raw.githubusercontent.com` доступен в сетях пользователей и возвращает корректные CORS-заголовки для публичных репозиториев.
  2. Chromium Manifest V3 разрешает выполнение простых cross-origin запросов (`fetch` с режимом `no-cors` и типом `text/plain`) из Content Script (Isolated World).
  3. `localStorage` страницы доступен и стабильно сохраняет состояние между сессиями браузера.

## Problem

### Object of Attention
Механизм дистанционной конфигурации продуктовых опросов и бессерверной доставки результатов голосования студентов при сохранении нулевой стоимости инфраструктуры и полной анонимности.

### Current State → Desired State
- *Исходное состояние (Current State):* Разработчик не имеет прямого канала обратной связи от активной аудитории (более нескольких сотен студентов) внутри интерфейса Modeus. Опросы в Telegram-каналах охватывают лишь малую часть пользователей и страдают от систематической ошибки выжившего (отвечают только самые активные, а не рядовые студенты).
- *Целевое состояние (Desired State):* Ненавязчивый нативный попап внутри интерфейса расписания, появляющийся только у реально активных студентов (таргетинг `config.targeting` на основе стажа и квалифицированных дней активности), управляемый дистанционно (включение/выключение за 1 минуту), с автоматическим сбором результатов в структурированную таблицу без затрат на хостинг.

### IF / THEN / BUT
- **IF:** Расширению требуется запустить интерактивный опрос студентов для выбора следующих фичей разработки,
- **THEN:** Конфигурация вопросов должна подтягиваться удаленно, а результаты надежно отправляться в хранилище без развертывания собственного бэкенда,
- **BUT:** Хранение вопросов внутри релизного архива порождает «зомби-опросы», внешние трекеры блокируются блокировщиками рекламы и нарушают приватность, а сторонние вебхуки блокируются браузером из-за CORS и 302-редиректов.

## Decision Drivers

1. **Zero Infrastructure Cost:** Нулевые финансовые и операционные затраты на серверную инфраструктуру.
2. **Decoupled Release Cycle:** Возможность запускать, менять и выключать опросы без выпуска патчей расширения.
3. **Student Privacy (Zero PII):** Гарантированная анонимность и отсутствие сбора персональных данных.
4. **Resilience & Silence:** При отсутствии сети или недоступности серверов опрос тихо пропускается, не вызывая сетевого спама, ошибок 404 и не влияя на расписание.
5. **No AdBlock Collisions:** Отказ от сторонних маркетинговых SDK, часто блокируемых расширениями uBlock Origin и AdGuard.

## Non-Goals (Явные границы отказа)

1. **Долговременное профилирование студентов:** Мы намеренно НЕ собираем цифровые отпечатки (fingerprints), User-Agent, экраны и историю кликов.
2. **Кросс-девайсная синхронизация статуса:** Если студент ответил на опрос на ноутбуке, мы не синхронизируем статус с его домашним ПК (достаточно локального сохранения в `localStorage`).
3. **Real-time дашборды внутри расширения:** Вся аналитика обрабатывается пассивно в Google Таблице автора без обратной связи в UI расширения.

## Alternatives

### Option A — Зашитый опрос в локальном пакете расширения (Hardcoded in Release Bundle)
- **Описание:** Поставлять `data/survey.json` внутри каждого ZIP-архива расширения.
- **Преимущества:** Работает оффлайн, не зависит от доступности внешних хостов.
- **Недостатки:**
  - Невозможно выключить опрос у пользователей старых версий («зомби-анкеты»).
  - Любое изменение вопроса или опечатки требует выпуска релиза и ожидания модерации.
- **Причина отказа:** Нарушает требование Decoupled Lifecycle и создает неуправляемый хвост устаревших версий.

### Option B — Сторонние платформы продуктовой аналитики (Mixpanel, Google Analytics, Amplitude)
- **Описание:** Встроить трекер аналитики для регистрации событий и фиксации ответов.
- **Преимущества:** Готовые дашборды и сегментация аудитории.
- **Недостатки:**
  - Блокируются большинством блокировщиков рекламы и приватных DNS (uBlock Origin, AdGuard).
  - Сбор системных идентификаторов (User-Agent, Canvas Fingerprint) вызывает обоснованные подозрения пользователей и противоречит политике проекта.
- **Причина отказа:** Нарушает принцип доверия и блокируется защитными расширениями студентов.

### Option C — Внешняя форма опроса (Google Forms / Яндекс Формы по ссылке)
- **Описание:** Отображать баннер со ссылкой на внешнюю форму опроса.
- **Преимущества:** Нулевая сложность реализации.
- **Недостатки:**
  - Катастрофически низкая конверсия (< 3%).
  - Выбивает студента из рабочего контекста (переход на внешнюю вкладку, требование логина Google).
- **Причина отказа:** Неприемлемый пользовательский опыт.

### Option D (Выбранное решение) — Remote Config (GitHub Raw) + Бессерверный Webhook (Google Apps Script)
- **Описание:** 
  1. Конфигурация хранится в репозитории проекта на GitHub (`data/survey.json`) и считывается через GitHub Raw CDN с локальным кэшированием (TTL 12 часов).
  2. В продакшен-сборку (ZIP) локальный файл не включается. При сбое сети опрос тихо пропускается.
  3. В режиме разработки (`mse_debug: "1"`) локальный файл считывается приоритетно для отладки без пушей.
  4. Телеметрия передается методом POST на Google Apps Script Web App в режиме `mode: 'no-cors'` с заголовком `Content-Type: text/plain`, скрипт аппендит строку в защищенную Google Таблицу автора.
- **Преимущества:**
  - Полный контроль над жизненным циклом опроса через git-коммит в main репозитория.
  - Бесплатный и надежный сбор данных в Google Таблицу.
  - Никаких блокировок CORS и блокировщиков рекламы.

## Decision Contract

### 1. Архитектура Remote Config и кэширования
- Конфигурация хранится в `https://raw.githubusercontent.com/student1245/Modeus-Student-Enhancer/main/data/survey.json`.
- Запрос выполняется из Isolated World (`src/content.js`) с таймаутом `FETCH_TIMEOUT_MS = 2500` мс.
- Успешный ответ сохраняется в `localStorage.mse_survey_cache` с временем жизни 12 часов (`SURVEY_CACHE_TTL_MS = 12 * 60 * 60 * 1000`).
- В продакшене опрос работает строго онлайн: если запрос к GitHub завершился сбоем и кэш отсутствует, загрузчик тихо возвращает `null` без обращения к локальному пакету и без спама ошибками 404 в консоль.
- В релизном GitHub Actions workflow (`.github/workflows/release.yml`) файл `data/survey.json` и каталог `data/*` принудительно исключаются из финального архива через флаг `-x`.

### 2. Пятиступенчатый предикат допуска к показу (`shouldShowSurvey`)
Показ опроса инициируется методом `checkSurvey()` только при одновременном выполнении 5 условий:
1. `config.enabled === true` — опрос включен автором на GitHub.
2. `localStorage.getItem('mse_surveys_disabled_forever') !== '1'` — пользователь не нажал «Никогда не спрашивать».
3. `localStorage.getItem('mse_survey_dismissed_' + config.id) !== '1'` — данный опрос еще не завершался и не отклонялся текущим пользователем.
4. `Date.now() > Number(localStorage.getItem('mse_survey_snooze_until') || 0)` — не активен таймер отсрочки «Позже» (3 дня).
5. Выполнены условия продуктового таргетинга `config.targeting` (Engagement-Based Retention: `minDaysSinceInstall`, `minQualifiedDays`, `minDailySecondsToQualify`, `minTotalActiveSeconds`).

### 3. Сетевой контракт телеметрии (`sendSurveyMetric`)
- **Метод:** `fetch(webhookUrl, { method: 'POST', mode: 'no-cors', headers: { 'Content-Type': 'text/plain' }, body: JSON.stringify(payload) })`
- **Обоснование `mode: 'no-cors'` и `text/plain`:**
  - Google Apps Script Web App при обработке POST-запроса выполняет внутренний 302-редирект на `script.googleusercontent.com`. Браузерный `fetch()` в стандартном режиме `cors` завершается фатальной ошибкой `TypeError: Failed to fetch`, так как редирект не сохраняет CORS-заголовки.
  - Режим `no-cors` с типом содержимого `text/plain` (simple request) отправляет запрос прозрачно без CORS preflight (OPTIONS) и успешно доставляет тело на бэкенд Google.
- **Анонимная структура полезной нагрузки:**
  - `timestamp`: строка ISO-8601.
  - `surveyId`: строковый идентификатор опроса.
  - `version`: версия расширения (например, `"2.2.3"`).
  - `action`: одно из трех событий (`"completed"`, `"declined"`, `"disabled_forever"`).
  - `answers`: объект с ответами (только при `action === 'completed'`). Отсутствуют любые персональные данные пользователя (IP, ФИО, email, student ID).

### 4. Разделение Dev vs Prod
- В dev-режиме (при флаге `mse_debug: "1"`) `src/content.js` приоритетно считывает локальный `data/survey.json`, позволяя автору мгновенно тестировать новые структуры опросов без пушей в GitHub.
- Метод `window.MSE_simulateSurvey(customConfig)` позволяет принудительно открыть попап с тестовым конфигом в любой момент в консоли.
- Метод `window.MSE_clearSurveyCache()` полностью сбрасывает кэш и все флаги скрытия (`mse_survey_dismissed_*`) для повторного тестирования.

## Consequences

### Positive
- Нулевые затраты на эксплуатацию: GitHub Raw и Google Apps Script абсолютно бесплатны для данного масштаба.
- Мгновенное управление: опрос можно включить, отредактировать или деактивировать простым коммитом в репозиторий.
- Полная конфиденциальность: отсутствие персональных данных исключает риски утечек и недовольство пользователей.
- Отсутствие зомби-опросов: пользователи без сети или со старыми архивами никогда не увидят неактуальные анкеты.

### Negative / Trade-offs
- Отсутствие тела ответа сервера при отправке метрики: из-за `mode: 'no-cors'` статус ответа в JavaScript всегда равен `0` (`opaque response`). Мы не можем программно прочитать ответ Apps Script, но гарантируется успешная сетевая доставка на бэкенд Google.
- Квоты Google Apps Script: бесплатное ограничение в 20 000 вызовов в сутки (для целевой аудитории расширения запас более чем десятикратный).

## Risks & Mitigations

| Риск | Влияние | Ранний сигнал | Митигация | Владелец |
|---|---|---|---|---|
| Блокировка `raw.githubusercontent.com` провайдерами | Среднее | `TypeError: Failed to fetch` в тихом режиме | Тихий fallback без ошибок; опрос просто не показывается | `student1245` |
| Исчерпание суточной квоты Apps Script (20k req/day) | Низкое | Ошибки HTTP 429 на сервере Google | Ограничение таргетинга `config.targeting` (квалифицированные дни) и разовый показ на опрос | `student1245` |
| Появление зомби-опроса из-за попадания survey.json в ZIP | Высокое | Наличие `data/survey.json` в релизном архиве | Исключение `-x "data/*"` в `.github/workflows/release.yml` | `student1245` |
| Спуфинг или спам вебхука пустыми запросами | Низкое | Замусоривание Google Таблицы | Валидация структуры payload в коде скрипта таблицы | `student1245` |

## Verification & Control

- **Observable Evidence:**
  - В консоли страницы при загрузке расписания с чистым кэшем: отсутствие сетевых ошибок 404 по пути `data/survey.json`.
  - В сетевом табе DevTools при отправке ответа: POST-запрос с типом `text/plain` и статусом `(opaque)` / `0`.
  - В целевой Google Таблице автора: появление строки с переданными ответами.
- **Success Criteria:**
  1. Попап появляется только при выполнении критериев таргетинга (`config.targeting`) и только один раз для каждого `surveyId`.
  2. В продакшен-релизе (ZIP) файл `data/survey.json` полностью отсутствует.
  3. При сбое сети или отсутствии интернета интерфейс расписания работает штатно, в консоли нет предупреждений.
- **Failure Criteria (Нарушение контракта):**
  1. Отправка POST-запроса в стандартном режиме `mode: 'cors'` (приводит к крашу `Failed to fetch`).
  2. Включение локального файла `data/survey.json` в продакшен-архив расширения.
  3. Сбор любых персональных идентификаторов студента (ФИО, email, student ID).
- **Verification Method:**
  - `window.MSE_simulateSurvey()` — принудительный запуск попапа в консоли для верификации UI.
  - `window.MSE_clearSurveyCache()` — сброс кэша и флагов скрытия для повторного прогона.

## Review Triggers

Контракт подлежит обязательному пересмотру при наступлении любого из событий:
1. Появление в самом Modeus официального встроенного механизма студенческих опросов.
2. Введение в Chrome Manifest V3 запрета на отправку простых `no-cors` запросов из Content Scripts.
3. Превышение суточной активности расширения свыше 20 000 отправок в день.
4. Отказ Google от поддержки веб-приложений Google Apps Script.

## Implementation Contract

### Scope
Подсистема удаленной конфигурации опросов и сбора телеметрии.

### Affected Areas
- `src/content.js` — загрузчик конфига с таймаутом 2500 мс и тихим пропуском, обработчик `mse_debug`.
- `src/injected.js` — модуль `checkSurvey()`, предикат `shouldShowSurvey()`, отправка метрик `sendSurveyMetric()`, методы отладки `window.MSE_*`.
- `styles/styles.css` — стили 4-экранного модального окна опроса.
- `data/survey.json` — локальный черновик для автора.
- `.github/workflows/release.yml` — исключение каталога `data/*` из продакшен-бандла.

### Patterns to Follow
- Использование `mode: 'no-cors'` и `headers: { 'Content-Type': 'text/plain' }` для обхода 302-редиректов Apps Script.
- Экранирование пользовательского ввода через `escapeHtml()` перед вставкой в DOM.
- Изоляция жизненного цикла: при любых сетевых сбоях тихо возвращать `null`.

### Patterns to Avoid (СТРОГИЙ ЗАПРЕТ)
- ❌ **ЗАПРЕЩЕНО** включать `data/survey.json` в релизные ZIP-архивы.
- ❌ **ЗАПРЕЩЕНО** собирать любые персональные данные (ФИО, почту, ID студента).
- ❌ **ЗАПРЕЩЕНО** использовать внешние коммерческие SDK аналитики (Mixpanel, GA).
- ❌ **ЗАПРЕЩЕНО** спамить сетевыми ошибками 404 в консоль пользователя при отсутствии локального конфига.
