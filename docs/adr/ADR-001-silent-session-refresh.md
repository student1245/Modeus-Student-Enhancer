# ADR-001: Бесшовное фоновое продление сессии (Session Keeper)

## Status

Accepted | Implemented (v2.2.3)

## Context

- **Initiator / Decision Owner:** `student1245`
- **Stakeholders:** Пользователи расширения Modeus Student Enhancer (студенты ТюмГУ), разработчики расширения.
- **Current state:** Механизм Session Keeper полностью реализован и функционирует в продакшене (версия v2.2.3).
- **Why now:** Фиксация архитектурного инварианта в виде нерушимого контракта (ADR). Необходимо защитить проверенное решение от регрессий и попыток «рефакторинга» в сторону `fetch()` или `window.location.href`, которые фатально ломают сессионную модель расширения из-за внешних платформенных ограничений.
- **Constraints:**
  1. *CORS Restriction:* Провайдер удостоверений ТюмГУ (`https://fs.utmn.ru/adfs/ls/`) и сервер авторизации (`https://auth.modeus.org/oauth2/authorize`) не отдают CORS-заголовки (`Access-Control-Allow-Origin: https://utmn.modeus.org`).
  2. *Fragment Loss:* Согласно спецификации W3C Fetch API / HTML Living Standard, при фоновом сетевом редиректе (HTTP 302) фрагмент URI (`#access_token=...`), через который OAuth 2.0 Implicit Flow возвращает токены, не передается вызывающему скрипту и безвозвратно теряется.
  3. *Zero External Dependencies:* Запрет на использование сторонних тяжелых библиотек (oidc-client, auth0 и др.); решение должно быть компактным и написанным на Vanilla JavaScript.
  4. *Chromium Context Boundary:* Разделение на Isolated World (`keeper-early.js`, `rules.json`) и Main World (`injected.js`).
- **Assumptions:**
  - Сессионные куки SSO на домене `fs.utmn.ru` остаются валидными в течение учебного дня.
  - Токен `id_token` имеет суточный срок действия (24 часа), что позволяет использовать его для валидации холодного старта.
- **Relevant external factors:**
  - Angular SPA платформы Modeus при получении первого же HTTP 401 принудительно перенаправляет роутер на форму входа.

## Problem

### Object of Attention
Жизненный цикл сессии авторизации студента в веб-клиенте Modeus (`https://utmn.modeus.org/*`) и предотвращение потери несохраненного состояния приложения при истечении времени жизни токена.

### Current State → Desired State
- *Исходное состояние платформы (Current State):* OAuth `access_token` выпускается со сроком жизни ровно 3600 секунд (1 час). По истечении часа все запросы к API возвращают 401, и Angular SPA сбрасывает страницу на экран логина, уничтожая несохраненный выбор элективов физкультуры, заполненные формы, фильтры расписания и открытые модальные окна.
- *Целевое состояние (Desired State):* Сессия поддерживается непрерывно (Zero-Logout Lifecycle) на протяжении всего времени работы браузера без участия пользователя, без моргания интерфейса и без потери фокуса/скролла. Открытие новых вкладок происходит мгновенно без повторного прохождения экрана логина.

### IF / THEN / BUT
- **IF:** Время жизни `access_token` истекает в процессе интерактивной работы студента в Angular SPA,
- **THEN:** Токен должен быть незаметно и гарантированно обновлен в фоновом режиме до первого сетевого отказа (HTTP 401),
- **BUT:** Сервер авторизации не поддерживает CORS для фонового `fetch()`, возвращает токены во фрагменте URL (`#access_token=...`) и запрещает показ страниц в iframe через заголовки `Content-Security-Policy: frame-ancestors` и `X-Frame-Options`.

## Decision Drivers

1. **Zero UX Disruption:** Полное отсутствие визуальных артефактов, моргания экрана, потери контекста SPA или сброса позиции скролла при рефреше.
2. **Абсолютная надежность:** Исключение сетевых ошибок HTTP 401 при длительной непрерывной работе вкладки (более 60 минут).
3. **Холодный старт без задержек:** Мгновенная гидратация сессии при открытии приложения в новой вкладке браузера без принудительного редиректа на страницу авторизации.
4. **Минимальная кодовая база:** Компактная нативная реализация без сторонних зависимостей.

## Alternatives

### Option A — Статус-кво платформы (Do Nothing)
- **Описание:** Использовать штатное поведение платформы Modeus: по истечении 1 часа сессия протухает, Angular выбрасывает на логин.
- **Преимущества:** Нулевые затраты на разработку.
- **Недостатки:** Крайне болезненный пользовательский опыт: студенты теряют выбранные команды при записи на физкультуру и сбивают открытые карточки расписания.
- **Причина отказа:** Напрямую противоречит ключевой миссии расширения — улучшению удобства работы с Modeus.

### Option B — Прямой редирект вкладки (`window.location.href`)
- **Описание:** При приближении срока истечения токена вызывать `window.location.href = authUrl`, проходя через SSO ТюмГУ и возвращаясь обратно.
- **Преимущества:** Не требует обхода CSP и заголовков фреймов.
- **Недостатки:** Полная перезагрузка страницы уничтожает состояние Angular SPA, прерывает таймеры, сбрасывает введенные данные и положение скролла.
- **Причина отказа:** Неприемлемо для интерактивной работы.

### Option C — Фоновый сетевой запрос (`fetch` / `XMLHttpRequest`)
- **Описание:** Инициировать фоновый запрос на эндпоинт `https://auth.modeus.org/oauth2/authorize` с `credentials: 'include'`.
- **Преимущества:** Чистый сетевой вызов без манипуляций с DOM.
- **Недостатки:** 
  1. Сервер ADFS ТюмГУ (`fs.utmn.ru`) не отдает заголовки CORS (`Access-Control-Allow-Origin`), в результате чего браузер блокирует ответ.
  2. Согласно стандарту Fetch, цепочка HTTP 302 теряет хэш-фрагмент с токенами (`#access_token=...`), делая извлечение токенов невозможным.
- **Причина отказа:** Физически не реализуемо в рамках стандартной веб-платформы.

### Option D — Скрытый iframe + DeclarativeNetRequest + Ранний бэкап (Выбрано)
- **Описание:** 
  1. Правила Chromium `declarativeNetRequest` вырезают заголовки `Content-Security-Policy` и `X-Frame-Options` в HTTP-ответах серверов `fs.utmn.ru` и `auth.modeus.org` исключительно для подфреймов (`sub_frame`).
  2. При приближении истечения токена в DOM монтируется скрытый `iframe#mse-silent-refresher`.
  3. Браузер проходит SSO-редиректы с сессионными куками ТюмГУ внутри фрейма и возвращается на `https://utmn.modeus.org/#access_token=...`.
  4. Родительское окно считывает токены из `iframe.contentWindow.location.hash` через Same-Origin доступ.
  5. Скрипт `keeper-early.js` на стадии `document_start` воскрешает сессию из `localStorage.mse_auth_backup` при открытии новой вкладки.
- **Преимущества:** 100% бесшовность для пользователя, отсутствие CORS-проблем, сохранение состояния SPA, мгновенный холодный старт, нативная реализация (~50 строк кода).
- **Недостатки:** Требует разрешения `declarativeNetRequest` и `host_permissions` в манифесте расширения.
- **Причина выбора:** Единственный технически состоятельный подход, обеспечивающий полное решение проблемы.

## Decision

Мы фиксируем архитектуру **Session Keeper** как связку трех обязательных компонентов:
1. **Сетевой уровень (DNR):** Снятие блокирующих заголовков фреймов через `rules.json` для доменов `fs.utmn.ru` и `auth.modeus.org`.
2. **Рантайм-рефреш (Main World):** Мониторинг здоровья токена каждые 20 секунд и тихий рефреш за 60 секунд до истечения через скрытый `iframe#mse-silent-refresher` с Same-Origin парсингом хэша и защитой от дожигания старого токена (`smartWaitTimer`).
3. **Холодный старт (Isolated World):** Резервное копирование 9 авторизационных ключей в `localStorage.mse_auth_backup` и их ранняя синхронизация в `sessionStorage` через `keeper-early.js` на этапе `document_start`.

### Why
Данная комбинация полностью решает проблему Zero-Logout Lifecycle, обходя платформенные ограничения безопасности без нарушения изоляции браузера и без деградации пользовательского опыта.

### Trade-offs
- Мы принимаем необходимость декларации расширенных прав расширения (`declarativeNetRequest`, доступ к хосту `https://fs.utmn.ru/*`) в обмен на стабильную и бесперебойную сессию пользователя.
- Мы принимаем хранение сессионных токенов в `localStorage` (с защитой через валидацию суточного срока `id_token` и обязательным удалением бэкапа при явном логауте) в обмен на мгновенный холодный старт в новых вкладках.

## Non-Goals

- Создание собственного OAuth-бэкенда или перехват/хранение паролей учетных записей ТюмГУ.
- Бесконечное продление сессии при истекшем суточном ID-токене (безопасность сохраняется: по истечении суток пользователь обязан пройти штатную аутентификацию).
- Поддержка браузеров без Manifest V3 / DeclarativeNetRequest.

## Consequences

### Positive
- Пользователи больше никогда не сталкиваются с внезапными выбросами на экран авторизации во время работы.
- Все несохраненные данные форм, модальных окон и выбора элективов сохраняются.
- Новые вкладки открываются сразу в авторизованном состоянии без задержек и редиректов.
- Нулевой оверхед по размеру бандла (отсутствуют внешние библиотеки).

### Negative / Trade-offs
- Расширение зависит от работоспособности Chromium DeclarativeNetRequest API.
- Необходимость сопровождения файла `rules.json` и синхронизации сессионных ключей.

### Risks

| Риск | Влияние | Ранний сигнал | Митигация | Владелец |

## Verification / Control

- **Decision Owner:** `student1245`
- **Evidence:** Логи консоли `[MSE Keeper] Сессия скоро истекает...` и `[MSE Keeper] Токен успешно продлен в фоне!`, отсутствие HTTP 401 в Network DevTools.
- **Success Criteria:**
  1. Вкладка работает непрерывно >60 минут без единой ошибки 401 и без редиректа на `/login`.
  2. Новая вкладка открывается с готовыми токенами в `sessionStorage` без показа страницы входа.
  3. Элемент `#mse-silent-refresher` удаляется из DOM в течение ≤12 секунд после создания.
  4. Обновление происходит бесшовно (0 мс блокировки UI, без моргания).
- **Failure Criteria (Нарушение контракта):**
  1. Появление хотя бы одного HTTP 401 Unauthorized на фоновых запросах Модеуса при открытой вкладке.
  2. Выброс на `/login` при открытии Модеуса в новой вкладке при валидном суточном ID-токене.
  3. Зависание элемента `#mse-silent-refresher` в DOM дольше 12 секунд (утечка элементов).
  4. Любое визуальное моргание интерфейса, потеря фокуса ввода или сброс позиции скролла при рефреше.
  5. Попытка внедрить сторонние OAuth-библиотеки в бандл вместо текущей нативной реализации.
- **Verification Method:**
  - Тестирование на реальном стенде `https://utmn.modeus.org/*`: оставить открытую вкладку на 65 минут и убедиться в успешном фоновом рефреше по таймстампам `access_token_stored_at`.
  - Открытие новой вкладки через `Ctrl+T` при заполненном бэкапе: проверка лога `[MSE Keeper] Сессия успешно реанимирована из бэкапа до старта приложения`.

## Review Triggers

Контракт является нерушимым и не подлежит произвольному пересмотру, **ЗА ИСКЛЮЧЕНИЕМ** наступления следующих событий:
1. **Официальный переход Modeus на Authorization Code Flow с PKCE** и включенным CORS на бэкенде авторизации (позволит перейти на чистый фоновый `fetch()` без использования DOM-фреймов).
2. **Официальное добавление домена `utmn.modeus.org` в заголовок `Content-Security-Policy: frame-ancestors`** сервера `fs.utmn.ru` (устранит необходимость сетевого правила в `rules.json`).
3. **Изменение политик безопасности Chromium**, запрещающее модификацию заголовков подфреймов через DeclarativeNetRequest API или Same-Origin доступ к фрагменту хэша внутри фрейма.

## Implementation Contract

### Scope
Подсистема **Session Keeper**: поддержание непрерывности авторизационной сессии в рантайме и ранняя гидратация контекста при холодном старте вкладки.

### Affected Areas
- `rules.json` — декларативные правила Chromium DNR.
- `manifest.json` — разрешения `declarativeNetRequest`, `storage`, секция `declarative_net_request` и `host_permissions` для `fs.utmn.ru`.
- `keeper-early.js` — ранний content script (`run_at: document_start`).
- `injected.js` — блок Session Keeper (функции `saveAuthTokensBackup`, `triggerSilentRefresh`, `monitorSessionHealth`, слушатель логаута).

### Required Changes & Behavior
1. `rules.json` обязан содержать правила `modifyHeaders` с удалением `content-security-policy` и `x-frame-options` для `resourceTypes: ["sub_frame"]` на фильтрах `||fs.utmn.ru` и `||auth.modeus.org`.
2. Мониторинг должен производиться регулярно (интервал 20 секунд) и запускать рефреш строго за 60 секунд до `expires_at`.
3. Фрейм `#mse-silent-refresher` обязан иметь стили скрытия:
   ```css
   position: absolute !important; width: 0 !important; height: 0 !important; border: none !important; display: none !important;
   ```
4. Чтение хэша должно выполняться по таймеру (интервал 50 мс) и событию `onload` фрейма.
5. При извлечении токенов обязательно обновлять `sessionStorage` (`access_token`, `access_token_stored_at`, `expires_at`, `id_token`, `session_state`) и немедленно вызывать `saveAuthTokensBackup()`.
6. Обязательна обработка дожигания старого токена сервером (`accessToken === oldToken && expiresIn <= 90` -> установка `smartWaitTimer`).
7. Обязателен предохранительный таймаут очистки фрейма на 12 секунд.
8. Скрипт `keeper-early.js` обязан проверять валидность `id_token_expires_at > Date.now()` перед восстановлением ключей в `sessionStorage`.
9. Обязателен слушатель кликов на селекторы логаута (`a[href*="logout"], button[id*="logout"], .logout-btn`) для удаления `mse_auth_backup`.

### Patterns to Follow
- Использование нативного DOM API и браузерного планировщика (`setInterval`, `setTimeout`).
- Same-Origin доступ к фрагменту URL (`location.hash`) дочернего фрейма после редиректа на целевой origin.
- Изоляция сетевых правил исключительно рамками подфреймов (`sub_frame`), чтобы не снижать безопасность основных вкладок пользователя.
- Идемпотентность и защита от параллельных рефрешей (`isSilentRefreshing` флаг).

### Patterns to Avoid (СТРОГИЙ ЗАПРЕТ)
- ❌ **ЗАПРЕЩЕНО** заменять скрытый iframe на вызовы `fetch()` или `XMLHttpRequest` для продления сессии (гарантированный отказ из-за отсутствия CORS и потери хэша при 302-редиректах).
- ❌ **ЗАПРЕЩЕНО** использовать `window.location.href` для обновления сессии (недопустимый сброс состояния Angular SPA, форм и фокуса).
- ❌ **ЗАПРЕЩЕНО** подключать сторонние OAuth / OIDC библиотеки (раздувание размера бандла и усложнение архитектуры).
- ❌ **ЗАПРЕЩЕНО** убирать проверку `id_token_expires_at` в `keeper-early.js` (риск зацикливания авторизации на протухших данных).

### Dependencies & Configuration
- Нативные API Chromium: `chrome.declarativeNetRequest`, `Storage API`.
- Внешние библиотеки: отсутствуют (0 зависимостей).

### Data Migration & Rollback
- При отказе механизма: удаление правил из `rules.json` и блока Session Keeper из `injected.js` возвращает стандартное поведение платформы Modeus (ручной логин каждый час).
- Формат хранилища `localStorage.mse_auth_backup` — JSON-объект словаря строковых ключей `AUTH_STORAGE_KEYS`.
