# ADR-002: Передача справочников через <meta>-теги (DOM Data Bridge) вместо window.postMessage

## Status

Accepted | Implemented (v2.2.3)

## Context

- **Initiator / Decision Owner:** `student1245`
- **Stakeholders:** Разработчики расширения Modeus Student Enhancer, пользователи веб-клиента Modeus.
- **Current state:** Механизм передачи баз корпусов, отзывов о преподавателях и версии расширения реализован и успешно функционирует в продакшене (v2.2.3).
- **Why now:** Фиксация архитектурного инварианта в виде нерушимого контракта (ADR). Передача данных через шину асинхронных сообщений (`window.postMessage` или `CustomEvent`) вносит недетерминированные гонки состояний (race conditions) в критический путь инициализации интерфейса расписания. Требуется явно зафиксировать запрет на внедрение асинхронных шин для предзагруженных статических баз данных.
- **Constraints:**
  1. *Chromium Context Boundary:* Скрипт `content.js` выполняется в контексте Isolated World и не имеет прямого доступа к объекту `window` страницы или переменным `injected.js` (Main World).
  2. *Content Security Policy (CSP):* Заголовки безопасности Modeus запрещают выполнение инлайн-скриптов (`unsafe-inline`), исключая возможность передачи данных через генерацию `<script>window.__DATA__ = ...</script>`.
  3. *Zero Race Conditions:* Справочник корпусов и отзывы должны быть доступны **синхронно на нулевой миллисекунде** работы `injected.js`, до старта таймера готовности DOM (`checkReady`) и первичного связывания событий FullCalendar.
  4. *Zero External Dependencies:* Решение должно опираться исключительно на стандартные DOM API браузера без привлечения сторонних библиотек сериализации или шин сообщений.
- **Assumptions:**
  - Браузер Chromium эффективно обрабатывает строки в атрибутах `content` тегов `<meta>` объемом в несколько сотен килобайт (текущий размер базы отзывов ~227 КБ, в Base64 ~300 КБ).
  - Скрипты, инжектируемые с `async = false`, выполняются синхронно в порядке их добавления в DOM после завершения текущего тика `content.js`.

## Problem

### Object of Attention
Механизм межконтекстной передачи данных (IPC) предварительно выгруженных баз данных (`buildings.json`, `teacher_reviews.json`) и версии расширения из изолированного контекста `content.js` в главный контекст страницы `injected.js` и `pe-module.js`.

### Current State → Desired State
- *Проблема альтернативных подходов (Current Problem):* При использовании классических каналов взаимодействия (`window.postMessage` или `CustomEvent`) передача данных носит асинхронный характер. Скрипт `injected.js` начинает монтирование UI, перехват сетевых запросов и связывание событий календаря до того, как обработчик сообщений получает базы. В результате при первой отрисовке в календаре отображаются сырые технические шифры («Корпус-1» вместо адреса), тултипы преподавателей не открываются, а код обрастает сложными промисами ожидания и таймаутами.
- *Целевое состояние (Desired State):* При старте выполнения `injected.js` все структуры данных (`buildingMap`, `teacherReviews`, `CURRENT_VERSION`) уже физически присутствуют в памяти страницы и считываются абсолютно синхронно, гарантируя корректное отображение интерфейса с первого кадра рендеринга.

### IF / THEN / BUT
- **IF:** Расширение запускается на странице Modeus и загружает актуальные справочники баз в контексте `content.js`,
- **THEN:** Эти данные должны быть синхронно доступны скрипту `injected.js` в момент его старта без задержек и ожидания асинхронных событий,
- **BUT:** Прямой доступ к переменным `window` страницы из `content.js` заблокирован архитектурой Chromium, инлайн-скрипты запрещены политикой CSP, а стандартные каналы межконтекстных сообщений (`window.postMessage`, `CustomEvent`) создают гонки состояний и требуют асинхронных рукопожатий (handshakes).

## Decision Drivers

1. **Детерминированная синхронность:** Доступность справочников на первом тике исполнения `injected.js` без ожидания промисов или событий.
2. **Zero Race Conditions:** Гарантия того, что календарь никогда не отрисуется до загрузки карты корпусов.
3. **Соответствие CSP:** Полное соответствие политикам безопасности страницы без использования `unsafe-inline` скриптов.
4. **Простота и надежность:** Отсутствие очередей сообщений, генерации уникальных ID запросов и двусторонних ACK-подтверждений.

## Alternatives

### Option A — Межконтекстные сообщения (`window.postMessage`)
- **Описание:** `content.js` после загрузки JSON отправляет `window.postMessage({ type: 'MSE_DATA_INIT', data: ... }, '*')`, а `injected.js` подписывается через `window.addEventListener('message')`.
- **Преимущества:** Стандартный документированный механизм передачи сообщений между контекстами в веб-платформе.
- **Недостатки:**
  1. Асинхронная природа: `injected.js` вынужден приостанавливать инициализацию и рендеринг календаря до прихода сообщения.
  2. Риск race condition: если сообщение отправлено до того, как `injected.js` зарегистрировал слушатель, оно теряется (требуется протокол двустороннего рукопожатия "ready -> ack").
  3. Безопасность: `window.postMessage` с целевым origin `*` виден любым сторонним скриптам страницы.
- **Причина отказа:** Неоправданное усложнение жизненного цикла старта и высокая вероятность рассинхронизации отрисовки.

### Option B — Пользовательские события DOM (`CustomEvent`)
- **Описание:** `content.js` диспатчит событие `document.dispatchEvent(new CustomEvent('mse-data-ready', { detail: ... }))`.
- **Преимущества:** Работает через нативный механизм событий DOM.
- **Недостатки:** Аналогично Option A: синхронно только при предварительно зарегистрированном слушателе. Поскольку порядок старта скриптов зависит от парсера браузера, возникает гонка состояний между регистрацией подписчика и вызовом события.
- **Причина отказа:** Те же риски потери данных и необходимость буферизации.

### Option C — Внедрение через inline `<script>` в DOM
- **Описание:** `content.js` создает элемент `<script>` и напрямую помещает сериализованные данные в `script.textContent = 'window.__MSE_DATA__ = ...;'`.
- **Преимущества:** Синхронное выполнение кода и прямая запись в `window`.
- **Недостатки:** Немедленно блокируется браузером из-за Content Security Policy приложения Modeus (`script-src 'self' ...`, запрещающей выполнение inline JavaScript без явного server-side nonce/hash).
- **Причина отказа:** Нарушает политики безопасности платформы и вызывает фатальную ошибку CSP в консоли.

### Option D — DOM Data Bridge через Base64 `<meta>`-теги (Выбрано)
- **Описание:**
  1. `content.js` сериализует текст JSON в Base64 через стандартный `TextEncoder`: побайтовое преобразование `Array.from(new TextEncoder().encode(text), b => String.fromCharCode(b)).join('')` → `btoa(...)`. Этот подход заменяет устаревший `btoa(unescape(encodeURIComponent(text)))` и является stack-safe при данных любого размера (защита от `RangeError: Maximum call stack size exceeded` в V8).
  2. Создает элементы `<meta name="..." content="...">` и синхронно монтирует их в `document.head`.
  3. Строго после добавления мета-тегов монтирует теги `<script src="pe-module.js">` и `<script src="injected.js">` с параметром `async = false`.
  4. Скрипт `injected.js` при старте синхронно считывает контент мета-тегов через `document.querySelector('meta[name="..."]')`, декодирует Base64 и мгновенно инициализирует переменные.
- **Преимущества:**
  - 100% синхронная доступность на этапе выполнения первой строки `injected.js`.
  - Полное соответствие CSP (атрибуты мета-тегов не являются исполняемым кодом).
  - Нулевой риск race conditions (теги уже в DOM в момент загрузки файла скрипта).
  - Простая реализация (~15 строк кода).
- **Недостатки:** Накладные расходы на кодирование и декодирование Base64 (+33% к размеру строки в памяти).
- **Причина выбора:** Идеальный баланс надежности, синхронности и простоты архитектуры.

## Decision

Мы фиксируем архитектурный паттерн **DOM Data Bridge через Base64 `<meta>`-теги** как единственный утвержденный способ передачи статических баз данных и конфигурации расширения из `content.js` в Main World (`injected.js` и `pe-module.js`).

### Why
Мета-теги в `<head>` являются валидными элементами DOM, полностью синхронно доступными для `document.querySelector()` в том же документе. Монтирование тегов до добавления `<script async="false">` физически исключает любые race conditions, сохраняя чистую и понятную синхронную модель старта приложения.

### Trade-offs
- Мы принимаем накладные расходы на кодирование строк в Base64 в `content.js` и их декодирование через `atob()` в `injected.js` в обмен на абсолютную синхронность данных и полное отсутствие асинхронных рукопожатий.

## Non-Goals

- Использование мета-тегов для динамического двустороннего взаимодействия компонентов во время работы приложения (динамическое взаимодействие в Main World выполняется напрямую через `window`).
- Передача огромных бинарных медиа-файлов (>10 МБ).

## Consequences

### Positive
- Гарантированная синхронная доступность данных корпусов, отзывов и версии на старте `injected.js`.
- Нулевой риск мигания интерфейса и отображения неразрешенных названий при открытии расписания.
- Полная невосприимчивость к строгим политикам безопасности CSP страницы.
- Исключение слушателей `window.onmessage` и устранение потенциальных уязвимостей перехвата сообщений сторонними скриптами.

### Negative / Trade-offs
- Небольшой оверхед процессора на этапе декодирования Base64 при холодном старте (менее 3–5 мс).
- Необходимость экранирования не-ASCII символов (кириллицы) через комбинацию `unescape(encodeURIComponent())` / `decodeURIComponent(escape())`.

### Risks

| Риск | Влияние | Ранний сигнал | Митигация | Владелец |
|---|---|---|---|---|
| Ошибка кодирования кириллических символов в Base64 | Высокое | Ошибки `InvalidCharacterError` в консоли браузера | Использование проверенной связки `unescape(encodeURIComponent(text))` и `decodeURIComponent(escape(atob(content)))` | `student1245` |
| Попытка запуска `injected.js` до монтирования мета-тегов | Критическое | `buildingMap` или `teacherReviews` пустые при старте | Строго последовательный `appendChild` в `content.js` и запрет на `async = true` | `student1245` |
| Разрастание базы отзывов свыше нескольких мегабайт | Среднее | Задержка DOM-парсинга при старте страницы | Ограничение размера локальной базы, сжатие данных при превышении 5 МБ | `student1245` |

## Verification / Control

- **Decision Owner:** `student1245`
- **Evidence:** Логи консоли браузера:
  - `[MSE] Загружено корпусов: N`
  - `[MSE] Загружено отзывов о преподавателях: M`
- **Success Criteria:**
  1. При первой отрисовке сетки расписания технические шифры («Корпус-1») мгновенно заменяются на человекочитаемые адреса без задержки.
  2. Тултипы преподавателей открываются с первого наведения курсора на карточку пары.
  3. Переменная `CURRENT_VERSION` в `injected.js` строго совпадает с версией из `manifest.json`.
- **Failure Criteria (Нарушение контракта):**
  1. Появление слушателей `window.addEventListener('message')` для начальной гидратации баз данных.
  2. Пустые структуры `buildingMap` или `teacherReviews` при выполнении `loadAllData()`.
  3. Появление ошибок нарушения CSP (`Refused to execute inline script...`) в консоли.
  4. Добавление флага `async = true` к инжектируемым скриптам `injected.js` или `pe-module.js`.
- **Verification Method:**
  - Проверка консоли DevTools при чистой загрузке страницы: отсутствие ошибок парсинга Base64 и наличие логов успешной загрузки структур данных.
  - Инспекция DOM в `Elements`: наличие в `<head>` тегов `<meta name="modeus-buildings-map">`, `<meta name="modeus-teacher-reviews">`, `<meta name="modeus-enhancer-version">`.

## Review Triggers

Контракт является стабильным и не подлежит произвольному пересмотру, **ЗА ИСКЛЮЧЕНИЕМ** следующих событий:

2. Появление в платформе Chromium / Manifest V3 официального механизма синхронного Shared Memory или типизированного синхронного IPC между Isolated World и Main World.

## Implementation Contract

### Scope
Канал передачи конфигурационных и справочных данных из `content.js` в `injected.js` / `pe-module.js`.

### Affected Areas
- `content.js` — модуль загрузки баз и формирования мета-тегов.
- `injected.js` — модуль чтения мета-тегов при старте (функция `loadDataFromMeta`, константа `CURRENT_VERSION`).
- `manifest.json` — декларация `web_accessible_resources` для загружаемых скриптов и файлов баз данных.

### Required Changes & Behavior
1. В `content.js` все мета-теги обязаны создаваться и добавляться в `document.head` **до** вставки скриптов:
   * `<meta name="modeus-buildings-map" content="...">`
   * `<meta name="modeus-teacher-reviews" content="...">`
   * `<meta name="modeus-enhancer-version" content="...">`
2. Кодирование текста в Base64 в `content.js` строго по формуле:
   ```javascript
   meta.content = btoa(unescape(encodeURIComponent(text)));
   ```
3. Инъекция скриптов `pe-module.js` и `injected.js` обязана производиться с флагом `async = false`:
   ```javascript
   const s = document.createElement('script');
   s.src = chrome.runtime.getURL('injected.js');
   s.async = false;
   (document.head || document.documentElement).appendChild(s);
   ```
4. В `injected.js` чтение мета-тегов обязано производиться синхронно в корневой самовызывающейся функции до любых операций с UI:
   ```javascript
   const json = decodeURIComponent(escape(atob(meta.content)));
   ```

### Patterns to Follow
- Синхронное монтирование атрибутов данных в DOM до запуска зависимого кода.
- Использование utf-8 безопасной Base64 сериализации для кириллических строк.
- Использование `chrome.runtime.getURL` в качестве надежного локального fallback при сбое загрузки с внешнего GitHub Raw.

### Patterns to Avoid (СТРОГИЙ ЗАПРЕТ)
- ❌ **ЗАПРЕЩЕНО** переводить передачу начальных баз данных на `window.postMessage` или `CustomEvent`.
- ❌ **ЗАПРЕЩЕНО** использовать инлайн-скрипты (`script.textContent = ...`) для передачи данных (нарушение CSP).
- ❌ **ЗАПРЕЩЕНО** выставлять флаг `async = true` на инжектируемых тегах `<script>`.
- ❌ **ЗАПРЕЩЕНО** откладывать чтение мета-тегов до асинхронных колбэков или событий таймера.

### Dependencies & Configuration
- Нативные API DOM: `document.createElement`, `document.head.appendChild`, `document.querySelector`.
- Внешние библиотеки: отсутствуют (0 зависимостей).

### Data Migration & Rollback
- При недоступности свежих баз с GitHub Raw (таймаут 2.5 с) скрипт `content.js` гарантированно использует встроенные локальные файлы `buildings.json` и `teacher_reviews.json`.
