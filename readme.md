# 📖 Документация: Modeus Student Enhancer (MSE) v2.1.0

**Modeus Student Enhancer** — это браузерное расширение (Manifest V3) для платформы `utmn.modeus.org` (Тюменский государственный университет). Оно значительно улучшает пользовательский опыт студентов, добавляя функции, которых нет в стандартном интерфейсе.

## ✨ Основные возможности (Фичи)
1. **Отзывы о преподавателях:** При наведении на имя преподавателя всплывает подсказка с отзывами студентов и рейтингом.
2. **Расшифровка корпусов:** Заменяет безликие номера корпусов (например, "Корпус-01") на их реальные названия ("Главный корпус").
3. **Список друзей:** Позволяет добавлять студентов в "Друзья", выводит их в боковое меню для быстрого просмотра их расписания.
4. **Поиск общих пар:** Добавляет строку поиска над календарем. Позволяет выбрать студентов и подсветить в расписании те пары, на которых вы пересекаетесь.
5. **Информация о студентах:** В списках студентов на парах добавляет информацию об их специальности.

## 📂 Структура проекта и описание файлов

### 1. `manifest.json`
Главный конфигурационный файл расширения (Manifest V3). 
* **`permissions`**: Запрашивает доступ к хранилищу (`storage`) для сохранения настроек, вкладкам (`tabs`) для перезагрузки страницы и скриптам (`scripting`).
* **`host_permissions`**: Ограничивает работу расширения только доменом `https://utmn.modeus.org/*`.
* **`content_scripts`**: Указывает, что файл `content.js` должен запускаться автоматически при загрузке страницы Modeus.
* **`web_accessible_resources`**: Разрешает веб-странице Modeus получить доступ к файлам расширения (`injected.js`, `buildings.json`, `teacher_reviews.json`). Это критически важно для обхода изоляции скриптов.

### 2. `popup.html` и `popup.js`
Пользовательский интерфейс расширения при клике на иконку в браузере.
* Содержит чекбокс для **включения/выключения** расширения (состояние сохраняется в `chrome.storage.sync`).
* Содержит кнопку для быстрой **перезагрузки вкладки**, чтобы изменения вступили в силу.

### 3. `buildings.json` и `teacher_reviews.json`
Статические базы данных расширения в формате JSON.
* **`buildings.json`**: Словарь для маппинга кодов корпусов в их читаемые названия.
* **`teacher_reviews.json`**: Обширная база отзывов о преподавателях. Содержит эмоциональную окраску (эмодзи), тип отзыва (Положительная/Отрицательная) и сам текст с форматированием.

### 4. `content.js` (Мост между расширением и страницей)
Content-скрипты работают в "изолированном мире" (Isolated World). Они видят DOM страницы, но не видят JavaScript-переменные страницы и не могут перехватывать её сетевые запросы. 
**Что делает `content.js`:**
1. Проверяет в хранилище, включено ли расширение.
2. Если включено, он считывает локальные файлы `buildings.json` и `teacher_reviews.json`.
3. Кодирует их в Base64 и **внедряет в `<head>` страницы в виде тегов `<meta>`** (например, `<meta name="modeus-buildings-map" content="...">`). Это хитрый способ передать данные из изолированного расширения в контекст самой веб-страницы.
4. Внедряет `injected.js` напрямую в DOM через тег `<script>`.

### 5. `injected.js` (Ядро логики расширения)
Этот скрипт работает в "главном мире" (Main World) веб-страницы. Он имеет полный доступ к объектам `window`, сетевым запросам `fetch` и роутеру Modeus. 

**Основные модули `injected.js`:**

* **Загрузка данных:** При запуске скрипт находит `<meta>` теги, оставленные `content.js`, декодирует Base64 и загружает справочники корпусов и преподавателей в память.
* **Перехват сетевых запросов (Network Sniffing):** 
  Переопределяет стандартные методы `window.fetch` и `XMLHttpRequest.prototype.send`. Если сайт делает запрос к `/api/people/persons/search` (поиск людей), скрипт "подслушивает" ответ, чтобы получить реальные ID студентов. Это нужно для работы системы друзей.
* **Система "Друзей":**
  * Сохраняет список добавленных друзей в `localStorage` (ключ `mse_friends_list`).
  * `renderFriendsMenu()`: Отрисовывает кастомную панель "Друзья" в боковом меню Modeus со ссылками на их расписание.
  * `updateAddFriendButtons()`: Добавляет сердечки (❤️/🤍) в выпадающие списки поиска студентов на сайте для быстрого добавления/удаления.
* **Поиск общих пар и обогащение данных API:**
  * `loadAllData()`: Делает прямые API-запросы к бэкенду Modeus, используя `id_token` из `sessionStorage`. Он выгружает все события (пары) пользователя на неделю и получает список всех студентов, присутствующих на этих парах.
  * Создает поисковую строку (`#enhancer-search-container`), позволяя искать студентов.
  * `highlightEventsForStudents()`: При выборе студентов, скрипт сверяет их со своим кэшем и подсвечивает (зеленой рамкой) те блоки календаря, где присутствуют выбранные люди.
* **Улучшение UI (Enhancers):**
  * `enhanceBuildingNames()`: Ищет в DOM текст формата "Корпус-XX" и заменяет его на нормальное имя по словарю.
  * `enhanceLists()`: Навешивает слушатели событий на имена преподавателей для показа кастомного `div` с всплывающей подсказкой (тултипом) из базы отзывов. Дописывает специальности к именам студентов.
* **Поддержка SPA (Single Page Application):**
  Поскольку Modeus работает без перезагрузки страниц (SPA), скрипт использует:
  * `MutationObserver`: Следит за любыми изменениями в DOM и заново применяет визуальные улучшения, если сайт перерисовал интерфейс.
  * Перехватчик `history.pushState` и событие `popstate`: Отслеживают изменения URL, чтобы корректно обновлять данные при переходах по страницам.

## ⚙️ Архитектурный процесс (Как это работает вместе)

1. Пользователь открывает `utmn.modeus.org`.
2. Браузер запускает `content.js`.
3. `content.js` читает JSON-файлы расширения, превращает их в строку, прячет в `<meta>` теги и встраивает `injected.js` в код страницы.
4. Скрипт `injected.js` запускается. Он распаковывает JSON из `<meta>` тегов.
5. `injected.js` запускает `MutationObserver`, который ждет, пока на странице не появятся нужные элементы (календарь, список меню).
6. Как только элементы появляются, скрипт добавляет строку поиска, переписывает корпуса и делает фоновые запросы к API Modeus для сбора данных о других студентах.
7. При наведении на преподавателя, скрипт берет его имя, ищет в словаре и рисует кастомный тултип.

## 🛠 Зачем сделан обход через `content.js` -> `<meta>` -> `injected.js`?
Сайт Modeus имеет строгую политику безопасности (CSP — Content Security Policy) и сложную SPA-архитектуру. 
Если бы вся логика была в `content.js`:
* Скрипт не смог бы достать токен авторизации из `sessionStorage` (часто изолируется).
* Скрипт не смог бы перехватить `fetch/XHR` запросы сайта.
Поэтому `content.js` используется исключительно как загрузчик, который "протаскивает" базу данных и основной скрипт (`injected.js`) внутрь среды самого сайта.
