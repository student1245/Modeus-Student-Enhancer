# 🏗 Архитектура: Modeus Student Enhancer (MSE) v2.2.2

В данном документе подробно описано внутреннее устройство расширения, жизненный цикл скриптов, механизмы взаимодействия с платформой Modeus (Angular SPA), модуль умного подбора физкультуры с функцией наложения расписания друга, система фонового обновления данных и алгоритмы поиска.

---

## 1. Общий стек и структура файлов

* **Архитектура расширения:** Manifest V3 (Google Chrome / Chromium).
* **Среда выполнения:** Клиентский JavaScript (ES6+), CSS3.
* **Целевой домен:** `https://utmn.modeus.org/*`

```text
Modeus-Student-Enhancer/
├── manifest.json            # Декларация расширения Manifest V3 и права доступа
├── popup.html / popup.js    # Всплывающее меню управления расширением (вкл/выкл)
├── content.js               # Загрузчик: фоновая загрузка баз с GitHub и инъекция в DOM
├── injected.js              # Главный скрипт: расписание, кэширование и поиск общих пар
├── pe-module.js             # Модуль умного подбора физкультуры и совместного выбора
├── pe-styles.css            # Стили полноэкранного интерфейса подбора физкультуры
├── buildings.json           # Локальный резервный справочник корпусов
├── teacher_reviews.json     # Локальный резервный справочник отзывов о преподавателях
└── icons/                   # Иконки расширения (16, 32, 48, 128 px)
```

## 2. Изоляция контекстов и обход CSP

Сайт Modeus является Single Page Application (Angular) со строгими политиками безопасности:
1. **Isolated World (изолированный мир `content.js`):** стандартные content-скрипты браузера не имеют доступа к JS-контексту `window`, не могут перехватывать системные запросы и читать `sessionStorage` с авторизационным JWT-токеном (`id_token`).
2. **Main World (контекст `injected.js` и `pe-module.js`):** скрипты внедряются напрямую в DOM страницы через тег `<script>`. Это дает полный доступ к `window.fetch`, `XMLHttpRequest`, `sessionStorage`, роутеру History API и контексту Angular.

### Мост передачи данных (`content.js` ➔ `<meta>` ➔ `injected.js`):
1. `content.js` читает локальные или удаленные JSON-файлы, а также версию из `manifest.json`.
2. Кодирует данные в Base64 и внедряет их в `<head>` в виде `<meta>`-тегов (`modeus-buildings-map`, `modeus-teacher-reviews`, `modeus-enhancer-version`).
3. Последовательно внедряет `<script src="pe-module.js">` и `<script src="injected.js">`.
4. Скрипты страницы мгновенно читают метаданные и инициализируют кэш.

## 3. Детальное описание компонентов

### 3.1. `content.js` (Smart Live Loader)
* **Фоновый подсос баз с GitHub:** асинхронные запросы с тайм-аутом 2.5 сек к `raw.githubusercontent.com` для скачивания свежих `teacher_reviews.json` и `buildings.json`.
* **Оффлайн-страховка (Fallback):** при сбое сети мгновенно переключается на локальные JSON-файлы расширения.
* **Проброс версии:** считывает актуальную версию из `manifest.json` и прокидывает ее на страницу через meta-тег.

---

### 3.2. `injected.js` (Ядро календаря и поиск общих пар)

#### А. Автоматическое определение контекста календаря (Защита от кэш-галлюцинаций)
* Декодирует JWT-токен из `sessionStorage` и извлекает постоянный `myPersonId`.
* **Детекция владельца экрана (`getActiveCalendarPersonId`):** парсит параметр `eventsFilter` в URL. Если пользователь просматривает расписание друга, `loadAllData` отправляет запросы к Calendar API **с ID просматриваемого человека**, а не владельца токена.
* При переключении между друзьями кэш `eventCache` и `uniqueStudents` полностью аннулируется, предотвращая ложное связывание параллельных пар в разных аудиториях.

#### Б. Связывание DOM и кэша (`linkDomEventsToCache`)
* Исключает дублирование: учитывает уже привязанные события через `assignedIds`.
* Сопоставляет карточки FullCalendar по точному времени начала и названию дисциплины.

#### В. Поиск общих пар и система «Друзья»
* Нормализация строк: удаление лишних пробелов, сведение регистра, замена **«Ё» на «Е»**.
* Приоритетное ранжирование подсказок по совпадению с начала фамилии.
* Меню быстрого перехода к расписанию друзей и кнопка «Вернуться к себе».

---

### 3.3. `pe-module.js` (Модуль «Умный подбор физкультуры»)

Специализированная подсистема для автоматизации и визуализации выбора элективов по физической культуре:

#### А. Сбор данных и слотовая сетка
* При нажатии «⚡ Умный подбор секций» запрашивает дерево кампании Booking API (`/student-campaign-menu`).
* Параллельно через `Promise.all` загружает команды модулей `/module-elements/{id}`.
* Запрашивает расписание на 21 день вперед (`POST /calendar/events/search`) и нормализует звонки пар к единым слотам (1–7 пара).

#### Б. Режим «Пойти с другом»
1. **Двухуровневый поиск ID друга (`getPersonIdByName`):**
   * *Уровень 1 (Offline):* Поиск по локальному списку `mse_friends_list` с очисткой «Е/Ё» и пробелов. Не генерирует сетевых запросов.
   * *Уровень 2 (Online):* Запрос к актуальному эндпоинту `POST /schedule-calendar-v2/api/people/persons/search` с полезной нагрузкой `{ fullName, sort: "+fullName", size: 10, page: 0 }`.
2. **Накладывание расписания друга:**
   * Скачивает события друга на 3 недели вперед.
   * **Независимое сравнение конфликтов:** разбирает множественные пары в слоте на массивы и сортирует их по алфавиту перед сравнением. Порядок прихода пар из API больше не влияет на сопоставление.
   * Если у обоих студентов стоят одинаковые предметы, слот маркируется: `⛔ У обоих пары (одинаковый предмет): Название`.

#### В. Защита интерфейса от CSS-сбросов Модеуса
* Панель поиска друга оформлена через жесткие inline-стили с `!important` и фиксированной шириной `260px`, предотвращая схлопывание стилей браузером и сдвиг сетки фильтров при изменении статуса.

#### Г. Запись и отмена через API
* Реализует прямую отправку запросов:
  - `POST .../module-elements/{id}/selected-teams` — запись в свободный модуль.
  - `DELETE .../module-elements/{id}/selected-teams` — отмена существующего выбора.
* Мгновенно пересчитывает доступные места и обновляет границы карточек (⭐) без перезагрузки страницы.

## 4. Схема потоков данных (Data Flow)

```text
[ Пользователь открывает utmn.modeus.org ]
                    │
                    ▼
          ┌───────────────────┐
          │    content.js     │ ◄─── Фоновый fetch к GitHub Raw (JSON баз)
          └─────────┬─────────┘      (Таймаут 2.5с -> Fallback на локальные JSON)
                    │
   Чтение manifest.json ➔ Запись <meta> в DOM 
   & Инъекция <script src="pe-module.js"> 
   & Инъекция <script src="injected.js">
                    │
                    ▼
          ┌───────────────────┐
          │    injected.js    │ ◄─── Декодирование баз и версии из <meta>
          └─────────┬─────────┘
                    │
     ┌──────────────┴────────────────────────────┐
     ▼                                           ▼
[ Модуль Расписания ]                  [ Модуль Физкультуры (pe-module.js) ]
  • Чтение id_token / personId           • Запрос дерева кампании и модулей
  • Загрузка событий и студентов         • Запрос пар студента (поиск конфликтов)
  • Кэш специальности и профиля          • Слотовая сетка расписания секций
  • Подсветка пар и бейджи (❤️, 🎓)       • Запись / Отписка (POST / DELETE API)
  • Проверка релизов (SemVer)            • Вывод отзывов и Яндекс Карт
```

## 5. Локальные хранилища (Storage Reference)

| Ключ | Хранилище | Назначение |
|---|---|---|
| `enabled` | `chrome.storage.sync` | Флаг глобального включения/отключения расширения |
| `mse_friends_list` | `localStorage` | Массив сохраненных друзей `[{id, fullName}]` |
| `mse_my_specialty` | `localStorage` | Автоматически определенное направление подготовки пользователя |
| `mse_my_profile` | `localStorage` | Автоматически определенный профиль подготовки пользователя |
| `mse_my_person_id` | `localStorage` | Идентификатор пользователя для возврата к своему расписанию |
| `mse_last_update_check` | `localStorage` | Timestamp последней проверки релиза на GitHub (кэш на 2 часа) |
| `mse_latest_release` | `localStorage` | JSON последнего проверенного релиза с GitHub |
| `mse_dismiss_update` | `sessionStorage` | Флаг скрытия всплывающего окна обновления на текущую сессию |
```
