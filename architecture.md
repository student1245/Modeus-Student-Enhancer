## 1. Общий стек и структура файлов

* **Архитектура расширения:** Manifest V3 (Google Chrome / Chromium).
* **Среда выполнения:** Клиентский JavaScript (ES6+), CSS3.
* **Целевой домен:** `https://utmn.modeus.org/*`

## 2. Изоляция контекстов и обход CSP

Сайт Modeus является Single Page Application (Angular) со строгими политиками безопасности:
1. **Isolated World (изолированный мир `content.js`):** стандартные content-скрипты браузера не имеют доступа к JS-контексту `window`, не могут перехватывать системные запросы и читать `sessionStorage` с авторизационным JWT-токеном (`id_token`).
2. **Main World (контекст `injected.js` и `pe-module.js`):** скрипты внедряются напрямую в DOM страницы через тег `<script>`. Это дает полный доступ к `window.fetch`, `XMLHttpRequest`, `sessionStorage`, роутеру History API и контексту Angular.

### Мост передачи данных (`content.js` ➔ `<meta>` ➔ `injected.js`):
1. `content.js` читает локальные или удаленные JSON-файлы, а также версию из `manifest.json`.
2. Кодирует данные в Base64 и внедряет их в `<head>` в виде `<meta>`-тегов (`modeus-buildings-map`, `modeus-teacher-reviews`, `modeus-enhancer-version`).
3. Последовательно внедряет `<script src="pe-module.js">` и `<script src="injected.js">`.
4. Скрипты страницы мгновенно читают метаданные и инициализируют кэш.

## 3. Детальное описание компонентов

### 3.1. `content.js` (Smart Live Loader)
* **Фоновый подсос баз с GitHub:** асинхронные запросы с тайм-аутом 2.5 сек к `raw.githubusercontent.com` для скачивания свежих `teacher_reviews.json` и `buildings.json`.
* **Оффлайн-страховка (Fallback):** при сбое сети мгновенно переключается на локальные JSON-файлы расширения.
* **Проброс версии:** считывает актуальную версию из `manifest.json` и прокидывает ее на страницу через meta-тег.

---

### 3.2. `injected.js` (Ядро календаря и поиск общих пар)

#### Защита от повторного запуска и глобальный реестр
* Скрипт обернут в IIFE и при старте проверяет `window.studentEnhancer`. Если объект уже существует, скрипт немедленно завершает работу, предотвращая дублирование слушателей и перехватчиков.
* При успешной инициализации в `window.studentEnhancer` сохраняются ссылки на `MutationObserver`, оригинальные функции `history.pushState`, `window.fetch` и `XMLHttpRequest.prototype.send`. Это позволяет корректно остановить расширение и восстановить исходное поведение страницы без перезагрузки.

#### Кнопка «Стоп-скрипт»
* В заголовок карточки события (`event-card-container__header`) динамически добавляется кнопка «Стоп-скрипт».
* При клике вызывается `stopAndCleanUp()`: отключается `MutationObserver`, восстанавливаются оригинальные `fetch`, `send` и `pushState`, удаляются все DOM-элементы расширения (панель поиска, тултипы, стили, меню друзей), очищается состояние поиска и удаляется `window.studentEnhancer`.

#### Перехват сетевых запросов (Network Interception)
* Функция `interceptNetworkRequests()` подменяет глобальные `window.fetch` и `XMLHttpRequest.prototype.send`.
* **Поиск людей:** ответы от `/api/people/persons/search` (и fetch, и XHR) клонируются, парсятся и складываются во временный in-memory кэш `lastSearchResults` (Map). После задержки 300 мс автоматически вызываются кнопки добавления в друзья.
* **Данные физкультуры:** ответы от `/module-elements/` парсятся, и если в JSON есть `cycles[0].teams`, сырые данные сохраняются в глобальную переменную `lastPeData` для дальнейшего использования модулем подбора секций.

#### Система «Друзья» (Friends Management)
* Хранение списка друзей в `localStorage` (ключ `mse_friends_list`) в формате `[{id, fullName}]`.
* Базовые операции: `getFriends`, `saveFriends`, `addFriend`, `removeFriend`.
* Генерация ссылок на расписание друга (`generateFriendUrl`): формирует URL `/schedule-calendar/my` с сериализованным JSON в параметре `eventsFilter`, где в `attendee` указан `personId` друга.
* Динамическое внедрение кнопок «Добавить в друзья» (🤍/❤️) в стандартный мультиселект Modeus (`.p-multiselect-item`). Кнопки реагируют на результаты перехваченного поиска людей.

#### Инъекция UI в боковое меню и футер
* `renderFriendsMenu()`: находит компонент PrimeNG (`modeus-main-menu p-panelmenu`) и дописывает в него выпадающую панель «Друзья» со списком сохраненных студентов, крестиками удаления и отдельной панелью «Вернуться к себе» (ведет на расписание владельца токена).
* `renderFooterFeedback()`: находит в `modeus-aside-panel` элемент с почтой `help@modeus.org` и аккуратно вставляет под ним ссылку на Telegram-бота для багов и отзывов.

#### А. Автоматическое определение контекста календаря (Защита от кэш-галлюцинаций)
* Декодирует JWT-токен из `sessionStorage` и извлекает постоянный `myPersonId`.
* **Детекция владельца экрана (`getActiveCalendarPersonId`):** парсит параметр `eventsFilter` в URL. Если пользователь просматривает расписание друга, `loadAllData` отправляет запросы к Calendar API **с ID просматриваемого человека**, а не владельца токена.
* При переключении между друзьями кэш `eventCache` и `uniqueStudents` полностью аннулируется, предотвращая ложное связывание параллельных пар в разных аудиториях.

#### Б. Связывание DOM и кэша (`linkDomEventsToCache`)
* Исключает дублирование: учитывает уже привязанные события через `assignedIds`.
* Сопоставляет карточки FullCalendar по точному времени начала и названию дисциплины.

#### Загрузка данных о парах и студентах (`loadAllData`)
* Извлекает даты текущей недели из DOM-элементов `.fc-day-header[data-date]`.
* Отправляет `POST /calendar/events/search` с `attendeePersonId` активного пользователя (а не владельца токена).
* Параллельно через `Promise.all` запрашивает список студентов (`/events/{id}/attendees`) для каждого события.
* Автоматически определяет специальность и профиль владельца токена (`mySpecialty`, `myProfile`), находя в списке посетителей события человека с совпадающим `personId`.
* Формирует `eventCache` (Map), где ключ — ID события, а значение включает короткое имя дисциплины, склеенное с названием модуля (`course-unit-realizations`), время начала и Set нормализованных имен студентов.

#### В. Поиск общих пар и подсветка расписания
* Панель поиска (`setupUI`) внедряется в тулбар календаря (`.main-calendar-form`) и содержит: статус загрузки, кнопки обновления и добавления друзей, поле ввода с автодополнением (до 7 подсказок, приоритет совпадению с начала фамилии), выпадающий список выбранных студентов.
* Кнопка «Добавить друзей в поиск» мгновенно заполняет выборку всеми сохраненными друзьями.
* `highlightEventsForStudents()`: карточки пар, где присутствуют выбранные студенты, получают зеленую рамку (`.search-highlight`), поверх контента карточки выводится блок с короткими именами (Фамилия И. О.), а в системный `title` пишутся полные имена. Остальные карточки затухают (`.search-fade`).
* `enhanceLists()`: ищет теги `<p>` с именами студентов и добавляет слева бейджи: ❤️ (друг), 🎓 (совпадает специальность и профиль). Выбранные студенты подсвечиваются зеленым фоном.
* Тултипы преподавателей: при наведении на имя преподавателя в списке создается плавающий `#teacher-tooltip` с отзывом из базы или заглушкой «Нет информации».

#### Улучшение названий корпусов (`enhanceBuildingNames`)
* Использует загруженный `buildingMap` для замены кодов вида `Корпус-XX` на читаемые названия.
* Применяется в трех местах: мелкие подписи времени в сетке календаря (`.fc-time small.text-muted`), всплывающие окна PrimeNG (`ngb-popover-window`) и заголовок локации в боковой карточке пары (`.location-info__header-text` + поле «ЗДАНИЕ»).
* Защита от повторной обработки через атрибут `data-enhanced-building`.

#### Г. Модуль успеваемости: отображение максимальных баллов (/my-results)

Подсистема визуализации максимальных баллов за контрольные точки на странице успеваемости (`https://utmn.modeus.org/students-app/my-results`).

##### 1. Назначение и логика работы
Штатный интерфейс Modeus выводит в ячейках таблицы только фактически полученный студентом балл (например, `2`, `4`), скрывая контекст максимальной стоимости пары.
Модуль решает задачу без вмешательства в недра Angular/RxJS через **пассивное чтение сети + DOM-модификацию**:
1. **Максимальные оценки (`val >= max`):** не загромождаются дробью, а выделяются зелёным подчёркиванием снизу (`.mse-max-done`).
2. **Неполные оценки (`val < max`):** получают аккуратную серую дробь (например, `1.36 /3`, `7.5 /10`).
3. **Множественные оценки (3+ точки на пару):** суммируются в единый итог за пару (например, `8 /8 | П`), предотвращая разрыв границ ячеек.
4. **Тултипы:** при наведении выводят полную детализацию по каждой задаче, включая потенциальные максимумы для несданных точек (`— / 3`).

---

##### 2. Структуры данных в памяти (In-Memory Cache)
* `mseCourseRealizationsMap (Map)`: Хранит нормализованное имя предмета ➔ хронологически отсортированный массив объектов пар (`lessons[]`).
* `mseLessonMaxGrades (Map)`: Связывает `lessonId` ➔ упорядоченный массив максимальных баллов `[max1, max2, ...]`.
* `mseLessonNameToMaxGrade (Map)`: Связывает имя пары ➔ массив максимальных баллов (для быстрого поиска в тултипах).
* `mseLoadedCourseUnits (Set)`: Хранит ID уже загруженных предметов для предотвращения дублирующих сетевых запросов.

---

##### 3. Сетевое взаимодействие (Используемые эндпоинты)

В финальной архитектуре сетевой перехватчик работает в **строго пассивном режиме** (Read-Only) — исходящие и входящие пакеты никак не мутируются:

1. **`POST /students-app/api/pages/student-card/my/academic-period-results-table/primary` (XHR)**
   * Перехватывается на событии `load` в `XMLHttpRequest.prototype.send`.
   * Извлекает структуру дисциплин `courseUnitRealizations[]` и сохраняет отсортированные по `orderIndex` пары.
   * Формирует список уникальных `courseUnitId` для скачивания техкарт.

2. **`GET /courses/api/course-units/{courseUnitId}/lessons-technology` (Fetch)**
   * Вызывается фоново расширением для каждого обнаруженного `courseUnitId` с авторизационным заголовком `Bearer {id_token}`.
   * Разбирает массив `lessonTechnologies[]` и извлекает упорядоченный список `controlObjects[].maxValue`.
   * По завершении триггерит первичное применение стилей через `enhanceGradesTable()`.

*(Эндпоинт `/secondary` не перехватывается, оценки считываются непосредственно из элементов DOM).*

---

##### 4. Алгоритмы рендеринга и обработки DOM

Код вызывается внутри `debouncedMutationHandler` при любых мутациях страницы:

1. **Связывание колонок (`enhanceGradesTable`):**
   * Находит в `thead` все заголовки, удовлетворяющие регулярному выражению `/Встреча\s*(\d+)/i`, определяя соответствие `индекс колонки -> номер встречи`.
   * Находит строку дисциплины в `tbody` через сопоставление `rowText.includes(courseName)`.
   * Извлекает соответствующий урок: `matchedLessons[meetingNumber - 1]`.

2. **Инъекция бейджей в ячейку (`injectMaxGradeBadge`):**
   * **Сценарий 3+ контрольных точек:** рассчитывает $\sum \text{Earned}$ и $\sum \text{Max}$. Заменяет содержимое первого спана на сумму с бейджем `createBadge(totalMax)`, а последующие спаны удаляет из DOM (`el.remove()`), предотвращая переполнение ячейки.
   * **Сценарий 1–2 контрольных точек:** проходит по спанам `.lesson-realization:not(.present):not(.absent)`. Если балл $\ge \text{max}$, вешает класс `.mse-max-done` (зеленое подчеркивание). Если балл $<\text{max}$, добавляет `.mse-max-grade` (` /${max}`).
   * **Защита текстовых узлов:** для неструктурированного текста использует сопоставление по регулярному выражению с сохранением неразрывных пробелов `\u00A0` перед тире незакрытых точек.

3. **Обогащение тултипов (`enhancePopovers`):**
   * Перехватывает всплывающие окна `ngb-popover-window, .popover, [role="tooltip"]`.
   * Находит блок с выставленной оценкой и форматирует в `${txt} / ${max}`.
   * Находит невыставленные контрольные точки (`/^[-–—]$/`) и преобразует их в `— / ${max}` с полупрозрачностью `0.6`.

#### Кнопка «Умный подбор секций» (интеграция с pe-module)
* MutationObserver отслеживает появление заголовка «Физическая культура» на страницах `/learning-path-selection/menus/`.
* Рядом с заголовком инжектится кнопка «⚡ Умный подбор секций».
* При клике кнопка самостоятельно собирает данные: запрашивает меню кампании, параллельно грузит команды всех модулей, скачивает расписание студента на 21 день вперед и строит карту занятых слотов (`blockedSlots` по дням недели и времени), исключая сами пары физкультуры.
* После сбора данных вызывает `window.MSE_PE.openModal(...)`, передавая модули, занятые слоты, ID кампании, ID студента и базу отзывов.

#### Проверка обновлений расширения (`checkExtensionUpdate`)
* Обращается к GitHub Releases API (`student1245/Modeus-Student-Enhancer`) не чаще одного раза в 2 часа (кэш в `localStorage`).
* Сравнивает версии по SemVer (покомпонентно).
* Если версия на GitHub выше: показывает оранжевый бейдж `⚡ vX.X.X` рядом с панелью поиска и всплывающее окно в правом нижнем углу с предложением скачать обновление. Окно можно закрыть на текущую версию (флаг `mse_dismissed_vX.X.X` в `localStorage`).

#### Реактивность и наблюдение за DOM
* Весь UI-код работает через `MutationObserver` на `document.body` с дебаунсом 250 мс (`debouncedMutationHandler`).
* Обработчик непрерывно поддерживает актуальность интерфейса: перелинковывает события, обновляет списки, улучшает корпуса, рендерит меню друзей (только на `/schedule-calendar/`), кнопку подбора физкультуры и кнопку остановки.
* Перехват навигации SPA: подменяется `history.pushState` и слушается `popstate`. Функция `processUrlChange` отслеживает параметр `selectedEvent` (для обновления тултипов при открытии карточки), смену фильтра `eventsFilter` (полная перезагрузка данных при переходе к другому человеку) и смену недели (имитация клика по кнопке обновления).

#### CSS-изоляция стилей
* Все стили расширения инжектятся тегом `<style id="enhancer-styles">` в `<head>`.
* Используются `!important` для критичных элементов (контейнер поиска, выпадающие списки), чтобы гарантировать отображение поверх штатных стилей Angular/PrimeNG.
* Боковая карточка события принудительно фиксируется шириной `325px` (`flex-shrink: 0`), чтобы injected-элементы не ломали верстку Modeus.

### 3.3. `pe-module.js` (Модуль «Умный подбор физкультуры»)

Специализированная подсистема для автоматизации и визуализации выбора элективов по физической культуре:

#### А. Сбор данных и слотовая сетка
* При нажатии «⚡ Умный подбор секций» запрашивает дерево кампании Booking API (`/student-campaign-menu`).
* Параллельно через `Promise.all` загружает команды модулей `/module-elements/{id}`.
* Запрашивает расписание на 21 день вперед (`POST /calendar/events/search`) и нормализует звонки пар к единым слотам (1–7 пара).

#### Б. Режим «Пойти с другом»
1. **Двухуровневый поиск ID друга (`getPersonIdByName`):**
   * *Уровень 1 (Offline):* Поиск по локальному списку `mse_friends_list` с очисткой «Е/Ё» и пробелов. Не генерирует сетевых запросов.
   * *Уровень 2 (Online):* Запрос к актуальному эндпоинту `POST /schedule-calendar-v2/api/people/persons/search` с полезной нагрузкой `{ fullName, sort: "+fullName", size: 10, page: 0 }`.
2. **Накладывание расписания друга:**
   * Скачивает события друга на 3 недели вперед.
   * **Независимое сравнение конфликтов:** разбирает множественные пары в слоте на массивы и сортирует их по алфавиту перед сравнением. Порядок прихода пар из API больше не влияет на сопоставление.
   * Если у обоих студентов стоят одинаковые предметы, слот маркируется: `⛔ У обоих пары (одинаковый предмет): Название`.

#### В. Защита интерфейса от CSS-сбросов Модеуса
* Панель поиска друга оформлена через жесткие inline-стили с `!important` и фиксированной шириной `260px`, предотвращая схлопывание стилей браузером и сдвиг сетки фильтров при изменении статуса.

#### Г. Запись и отмена через API
* Реализует прямую отправку запросов:
  - `POST .../module-elements/{id}/selected-teams` — запись в свободный модуль.
  - `DELETE .../module-elements/{id}/selected-teams` — отмена существующего выбора.
* Мгновенно пересчитывает доступные места и обновляет границы карточек (⭐) без перезагрузки страницы.

## 4. Схема потоков данных (Data Flow)

```text
[ Пользователь открывает utmn.modeus.org ]
                    │
                    ▼
          ┌───────────────────┐
          │    content.js     │ ◄─── Фоновый fetch к GitHub Raw (JSON баз)
          └─────────┬─────────┘      (Таймаут 2.5с -> Fallback на локальные JSON)
                    │
   Чтение manifest.json ➔ Запись <meta> в DOM 
   & Инъекция <script src="pe-module.js"> 
   & Инъекция <script src="injected.js">
                    │
                    ▼
          ┌───────────────────┐
          │    injected.js    │ ◄─── Декодирование баз и версии из <meta>
          └─────────┬─────────┘
                    │
     ┌──────────────┴────────────────────────────┐
     ▼                                           ▼
[ Модуль Расписания ]                  [ Модуль Физкультуры (pe-module.js) ]
  • Чтение id_token / personId           • Запрос дерева кампании и модулей
  • Загрузка событий и студентов         • Запрос пар студента (поиск конфликтов)
  • Кэш специальности и профиля          • Слотовая сетка расписания секций
  • Подсветка пар и бейджи (❤️, 🎓)       • Запись / Отписка (POST / DELETE API)
  • Проверка релизов (SemVer)            • Вывод отзывов и Яндекс Карт
```
