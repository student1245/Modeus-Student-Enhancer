# 🏗 Архитектура: Modeus Student Enhancer (MSE) v2.2.1

В данном документе подробно описано внутреннее устройство расширения, жизненный цикл скриптов, механизмы взаимодействия с платформой Modeus (Angular SPA), модуль умного подбора физкультуры, система фонового обновления данных и алгоритмы поиска.

---

## 1. Общий стек и структура файлов

* **Архитектура расширения:** Manifest V3 (Google Chrome / Chromium).
* **Среда выполнения:** Клиентский JavaScript (ES6+), CSS3.
* **Целевой домен:** `https://utmn.modeus.org/*`

```text
Modeus-Student-Enhancer/
├── manifest.json            # Декларация расширения Manifest V3 и права доступа
├── popup.html / popup.js    # Всплывающее меню управления расширением (вкл/выкл)
├── content.js               # Загрузчик: фоновая загрузка баз с GitHub и инъекция в DOM
├── injected.js              # Главный скрипт: бизнес-логика расписания в контексте страницы
├── pe-module.js             # Модуль умного подбора физкультуры (UI и API-запросы)
├── pe-styles.css            # Стили полноэкранного интерфейса подбора физкультуры
├── buildings.json           # Локальный резервный справочник корпусов
├── teacher_reviews.json     # Локальный резервный справочник отзывов о преподавателях
└── icons/                   # Иконки расширения (16, 32, 48, 128 px)
```

## 2. Изоляция контекстов и обход CSP (Content Security Policy)

Сайт Modeus является Single Page Application (Angular) со строгими политиками безопасности:
1. **Isolated World (изолированный мир `content.js`):** стандартные content-скрипты браузера не имеют доступа к JS-контексту `window`, не могут перехватывать системные запросы и читать `sessionStorage` с авторизационным JWT-токеном (`id_token`).
2. **Main World (контекст `injected.js` и `pe-module.js`):** скрипты внедряются напрямую в DOM страницы через тег `<script>`. Это дает полный доступ к `window.fetch`, `XMLHttpRequest`, `sessionStorage`, роутеру History API и открытому контексту Angular.

### Мост передачи данных (`content.js` ➔ `<meta>` ➔ `injected.js`):
1. `content.js` читает локальные или удаленные JSON-файлы, а также версию из `chrome.runtime.getManifest().version`.
2. Кодирует данные и внедряет их в `<head>` в виде `<meta>`-тегов:
   - `<meta name="modeus-buildings-map" content="...">`
   - `<meta name="modeus-teacher-reviews" content="...">`
   - `<meta name="modeus-enhancer-version" content="2.2.1">`
3. Последовательно внедряет `<script src="pe-module.js">` и `<script src="injected.js">`.
4. Скрипты страницы мгновенно читают метаданные и запускают бизнес-логику.

## 3. Детальное описание компонентов

### 3.1. `content.js` (Smart Live Loader)
* **Фоновый подсос баз с GitHub:** асинхронные запросы с тайм-аутом 2.5 сек к `raw.githubusercontent.com` для скачивания свежих `teacher_reviews.json` и `buildings.json`.
* **Оффлайн-страховка (Fallback):** при сбое сети мгновенно переключается на локальные JSON-файлы расширения.
* **Проброс версии:** считывает актуальную версию из `manifest.json` и прокидывает ее на страницу через meta-тег.

### 3.2. `injected.js` (Ядро системы)

#### А. Автоматическое определение профиля и токена
* Декодирует JWT-токен из `sessionStorage` и получает `personId`.
* При первой выгрузке посещаемости пар автоматически определяет специальность (`specialtyName`) и профиль (`specialtyProfile`) пользователя, кэшируя их в `localStorage` (`mse_my_specialty` и `mse_my_profile`).

#### Б. Поиск общих пар (`loadAllData`)
* Выгружает события недели через POST `/schedule-calendar-v2/api/calendar/events/search` и списки участников через `/calendar/events/{id}/attendees`.
* Нормализует имена (удаление лишних пробелов, замена **«Ё» на «Е»**).
* Реализует поиск с приоритетом совпадения по **фамилии** (ранжирование) и подсветку пар на сетке FullCalendar (`.search-highlight` и `.search-fade`).

#### В. Система «Друзья» и навигация
* Сохранение друзей в `localStorage (mse_friends_list)`.
* Встраивание пунктов меню **«Друзья»** и **«Вернуться к себе»** в боковую панель `modeus-main-menu`.
* Быстрое добавление (❤️ / 🤍) в выпадающих списках поиска людей.

#### Г. Обогащение списков студентов (`enhanceLists`)
* ❤️ — студент добавлен в друзья.
* 🎓 — строгое совпадение **и направления, и профиля подготовки** с текущим пользователем.
* Зеленый маркер — студент выбран в поиске общих пар.

#### Д. Оповещение об обновлениях (`checkExtensionUpdate`)
* Опрашивает GitHub Releases API (`/releases/latest`) не чаще одного раза в 2 часа (кэш в `localStorage`).
* Использует алгоритм семантического сравнения версий (**SemVer**), исключающий ложные срабатывания.
* Выводит бейдж `⚡ vX.X.X` и модальное окно со ссылкой на список изменений.

### 3.3. `pe-module.js` (Модуль «Умный подбор физкультуры»)

Специализированная подсистема для автоматизации и визуализации выбора элективных дисциплин по физической культуре:

#### А. Интеграция в SPA-интерфейс
* Отслеживает переход на страницы `/learning-path-selection/menus/`.
* При обнаружении кампаний физической культуры встраивает кнопку **«⚡ Умный подбор секций»** в заголовок страницы.

#### Б. Сбор данных и детекция конфликтов
* При нажатии кнопки обращается к Booking API Modeus:
  - `GET /students/{studentId}/campaigns/{campaignId}/student-campaign-menu` — получает список модулей.
  - Параллельно через `Promise.all` запрашивает команды каждого модуля `/module-elements/{id}`.
* Запрашивает расписание студента на 21 день вперед через Calendar API (`POST /events/search` по `person_id`).
* **Слотовое сопоставление времени:** нивелирует 5–10 минутную разницу звонков между лекциями и физкультурой (12:00 vs 12:05, 14:00 vs 14:05, 15:45 vs 15:55 и т.д.), приводя всё к единым слотам пар (1–7 пара).
* Ячейки с парами из расписания блокируются плашкой *«🎓 У вас пара: Название»*, а конфликтующие секции скрываются.

#### В. База гео-локаций и нормализация
* Нормализует спортивные дисциплины (очищает склеенные названия залов).
* Сопоставляет шифры Модеуса (`УЛК-13`, `07 СК`, `УЛК-05`, `Ул.Рощинское шоссе`) с реальными названиями (*Эко-парк*, *Олимпия*, *Матфак*, *Биофак*, *Аграрный уник*) и генерирует ссылки на Яндекс Карты.
* Подтягивает отзывы на преподавателей из `teacher_reviews.json`.

#### Г. Запись и отмена через API
* Реализует прямую отправку запросов:
  - `POST .../module-elements/{id}/selected-teams` — запись в свободный модуль.
  - `DELETE .../module-elements/{id}/selected-teams` — отмена существующего выбора.
* Мгновенно пересчитывает доступные места и обновляет границы карточек (⭐) без перезагрузки страницы.

## 4. Схема потоков данных (Data Flow)

```text
[ Пользователь открывает utmn.modeus.org ]
                    │
                    ▼
          ┌───────────────────┐
          │    content.js     │ ◄─── Фоновый fetch к GitHub Raw (JSON баз)
          └─────────┬─────────┘      (Таймаут 2.5с -> Fallback на локальные JSON)
                    │
   Чтение manifest.json ➔ Запись <meta> в DOM 
   & Инъекция <script src="pe-module.js"> 
   & Инъекция <script src="injected.js">
                    │
                    ▼
          ┌───────────────────┐
          │    injected.js    │ ◄─── Декодирование баз и версии из <meta>
          └─────────┬─────────┘
                    │
     ┌──────────────┴────────────────────────────┐
     ▼                                           ▼
[ Модуль Расписания ]                  [ Модуль Физкультуры (pe-module.js) ]
  • Чтение id_token / personId           • Запрос дерева кампании и модулей
  • Загрузка событий и студентов         • Запрос пар студента (поиск конфликтов)
  • Кэш специальности и профиля          • Слотовая сетка расписания секций
  • Подсветка пар и бейджи (❤️, 🎓)       • Запись / Отписка (POST / DELETE API)
  • Проверка релизов (SemVer)            • Вывод отзывов и Яндекс Карт
```

## 5. Локальные хранилища (Storage Reference)

| Ключ | Хранилище | Назначение |
|---|---|---|
| `enabled` | `chrome.storage.sync` | Флаг глобального включения/отключения расширения |
| `mse_friends_list` | `localStorage` | Массив сохраненных друзей `[{id, fullName}]` |
| `mse_my_specialty` | `localStorage` | Автоматически определенное направление подготовки пользователя |
| `mse_my_profile` | `localStorage` | Автоматически определенный профиль подготовки пользователя |
| `mse_my_person_id` | `localStorage` | Идентификатор пользователя для возврата к своему расписанию |
| `mse_last_update_check` | `localStorage` | Timestamp последней проверки релиза на GitHub (кэш на 2 часа) |
| `mse_latest_release` | `localStorage` | JSON последнего проверенного релиза с GitHub |
| `mse_dismiss_update` | `sessionStorage` | Флаг скрытия всплывающего окна обновления на текущую сессию |
```
